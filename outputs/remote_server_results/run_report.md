# ExposureAgent 远程实验结果与分析报告

实验日期：2026-08-26  
实验性质：工程链路 Smoke Test，不是正式模型效果实验

## 1. 实验目的

本次实验主要验证以下链路能否在 RTX 4090 服务器上完整运行：

1. 加载开源 Qwen2.5-VL；
2. 读取曝光图像及 ISO、快门、EV 参数；
3. 使用 LoRA 执行真实前向传播和反向传播；
4. 保存并重新加载训练后的 LoRA Adapter；
5. 执行 VLM 曝光 Action 预测、RAG 检索、停止条件判断；
6. 输出结构化 JSON 实验记录。

本次只训练了 1 step，目的是确认代码能更新模型参数，不用于证明模型已经学会曝光控制。

实际 Pipeline 为：

```text

        ↓

        ↓

        ↓
Policy 检查 continue 与动作阈值
        ↓
满足停止条件，网格搜索和图像模拟被跳过
        ↓
结束，最终图像保持为输入图像
```

## 6. 实验结果分析

### 6.1 工程链路已经跑通

本次实验已经证明以下工程能力可用：

- RTX 4090 可以加载 Qwen2.5-VL-3B 并进行 LoRA 训练；
- 图像和曝光参数可以进入多模态模型；
- 模型能够输出可被严格 parser 接受的 JSON；
- RAG 能返回曝光经验；
- Agent 能根据停止条件保存完整的结构化结果；
- LoRA checkpoint 能保存并重新接入推理。

因此，项目已经具备开展正式数据构建与训练实验的基础。

### 6.2 当前曝光决策不合理

输入图像在视觉上明显偏暗，`brightness=0.2209` 也支持这一判断。RAG 中几乎完全相同的历史样本建议增加 ISO、EV 和快门时间，并记录了正向质量增益。然而 VLM 最终给出的却是 no-op，并立即终止循环。

这说明当前 VLM 的 Action 预测还不可靠。主要原因是训练集只有约 10 条弱监督记录，并且本次只训练了 1 step。`loss=1.963` 只能说明优化器执行成功，不能说明模型已经获得曝光控制能力。

### 6.3 VLM 可能没有独立完成图像质量判断

当前 Prompt 会把 `ImageEvaluator` 计算出的 `objective_quality` 一起发送给 VLM，而本次 VLM 返回的各项质量数值与 evaluator 数值完全一致。这更像是在复述输入指标，而不是独立观察图像后估计质量。

论文实验应明确选择以下一种定义：

- 如果研究的是纯 VLM 图像质量判断，应从 Prompt 中移除 `objective_quality`，只给图像与曝光参数；
- 如果研究的是 evaluator-assisted VLM，应明确说明质量指标由传统算法提供，VLM 主要负责 Action 决策。

不能把当前结果直接表述成“VLM 独立准确判断了图像质量”。

### 6.4 motion_blur 指标存在误判风险

当前 `motion_blur` 使用 `1 - edge_energy * 12` 计算。输入图像偏暗、整体对比度较低，会直接降低边缘能量，因此即使色卡边缘肉眼仍然较清晰，也可能得到接近 1 的模糊分数。

该指标目前混合了低曝光、低对比度和真实运动模糊，不能直接作为运动模糊标签。后续建议使用 Laplacian variance、频域高频能量，或者带真实模糊标注的数据进行校准。

### 6.5 本次 RAG 结果不能证明泛化能力

RAG top-1 的距离接近 0，是因为 Memory 中包含同一个 `0001_001` 场景及几乎相同的输入特征。这只能证明检索功能工作正常，不能证明系统能为未见场景找到有效经验。

正式评估必须按 scene ID 划分训练、Memory 和测试集合，确保测试场景不会以任何 iteration 形式出现在 RAG Memory 中。

### 6.6 当前停止顺序会放大错误 VLM 决策

当前流程先检查 VLM 的 `continue`，再决定是否进入 RAG Action 融合和网格搜索。于是只要尚未训练好的 VLM 错误输出 `continue=false`，即使 RAG 已找到明显有效的历史策略，后续搜索仍会被直接跳过。

从论文方案角度有两种处理方式：

1. 保持 VLM 绝对控制权，但需要先把 VLM 训练到足够可靠；
2. 增加冲突处理机制，当图像客观质量明显不合格且 RAG 存在正增益经验时，不允许单独由 `continue=false` 提前终止。

第二种更容易让当前系统跑出完整闭环，但需要在论文中明确它属于 Policy 规则，而不是 VLM 自主决策。

## 7. 本次实验发现并修复的工程问题

1. SIDD 高分辨率图像最初产生约 16,320 个视觉 token，超过序列长度。现已增加 `max_pixels=401408`，将输入限制在约 512 个视觉 token。
2. Qwen 在带 RAG Prompt 时偶尔漏掉 JSON 的 `quality` 字段。现已增加一次显式格式纠正重试，第二次仍不合法时继续报错，不使用默认值伪造结果。
3. 单元测试曾向默认 Memory 写入测试渐变图经验。最终实验已经改用独立的 SIDD Memory 文件。
4. 结构化报告现在会明确记录网格搜索是否执行以及跳过原因。

## 8. 结论与下一步实验

本次实验结论是：项目工程 Pipeline 已经在 RTX 4090 上跑通，VLM 参数能够通过 LoRA 反向传播更新，结构化输出、RAG 和停止机制均可执行；但当前不能证明模型已经学会正确调整曝光。

下一轮正式实验应完成：

1. 将训练样本扩充到至少数百条，并去除重复 iteration；
2. 按 scene ID 划分训练集、验证集、测试集和 RAG Memory；
3. 分别评估基础模型与 LoRA 模型；
4. 统计 JSON 合法率、Action 数值误差、质量提升量、平均循环轮数和错误停止率；
5. 单独消融 VLM、RAG、局部搜索三个模块；
6. 在有真实相机或真实多曝光序列前，将 Simulator 结果表述为曝光近似模拟，不作为真实重新拍摄结果。
